# 保留原文段落与列表结构

本轮依据用户提供的两个截图：同一解析框内包含两个带粗体标题的列表项，以及两个首行缩进的正文段落。旧代码先把块内换行归一为空格，再把各要点译文用空格拼接；源结构没有进入渲染数据，因而被挤成连续文字。

## RetainPDF 参考

已读取上游源码，固定版本 `a665c2aea2cd0860c737e7f9685d8071fbef1b3a`：

- [首行缩进](https://github.com/wxyhgk/retain-pdf/blob/a665c2aea2cd0860c737e7f9685d8071fbef1b3a/backend/pipeline/retainpdf_pipeline/render/layout/payload/first_line_indent.py)：从文字层的行起点测量缩进，区分没有缩进和无法读取。
- [结构化行](https://github.com/wxyhgk/retain-pdf/blob/a665c2aea2cd0860c737e7f9685d8071fbef1b3a/backend/pipeline/retainpdf_pipeline/render/layout/payload/line_structure.py)：保留源行与结构标记，并区别普通软换行和应保留的列表结构。

本插件适配了上述列表标记和缩进规则，MIT 许可与归属见 `NOTICE.md` 和随插件打包的 `content/lib/retainpdf/LICENSE`。本轮使用 Zotero 的 PDF.js 文字层和 DOM 渲染；没有引入完整的 Typst/PDF 重绘后端。

## 实现

1. 在换行归一化之前，根据文字坐标、行距、缩进和列表符号提取 `translationLayout.units`。每一项保留固定 ID、类型、原文、原文强调、列表符号、首行／悬挂缩进及源高度比例。
2. 含多个真实段落或列表项时，逐页请求携带固定 `source layout units`，模型用 `layout_translations` 按 ID 分别返回译文；缺项、重复 ID 或未知 ID 不被采纳。要点分组不再决定译文的段落结构。
3. 单段可复用原有要点译文；多段仅在要点确实落在唯一源段落内时复用。旧混合译文无法可靠分配时，按源单元补译，不按字符长度猜测切分位置。
4. 显示时由代码恢复列表标记、悬挂缩进和段落缩进；原段落对应不同的 DOM 单元，按源高度预留空间。模型自己添加的换行不创建新段落。字体仍有可读性下限，超长译文允许滚动，不删减内容。
5. 旧缓存打开后从本地 PDF 文字层恢复结构，仅对缺失的译文单元追加请求，不重新调用 MinerU。成功的结构和译文会保存；取消／重新精读时丢弃过期结果。多段或列表结构不会被跨页续段功能压成一个段落。

独立公式、含显示公式的合并段落和图注沿用既有通道。扫描件缺少文字坐标、OCR 内容与文字层不匹配、复杂嵌套列表等情况可能无法恢复全部结构；这不等于任意 PDF 的像素级复刻。

## 悬停译文的可视范围与关闭

普通段落、续段和图注现在都以阅读器当前可视窗口为边界，避免把译文放到整页内但屏幕外。仍优先保持原文宽度和近似高度；窗口过窄或上下空间不足时限制弹层尺寸，让完整译文在框内滚动，不继续压缩到难以辨认的字号。单栏会优先使用原文上方或下方的空余位置。

长译文可以获得键盘焦点，鼠标离开后不会在定时器到期时消失。按 Esc 会立即收起译文，并等鼠标离开该段后才允许再次悬停显示。滚动 PDF 会清理旧弹层，避免留下已经偏离原文位置的译文。深色主题保留文字和焦点边框对比度。这些调整不改变模型请求或原文结构协议。

## 卡片交互与颜色

正常布局的卡片以前移除“展开”状态后仍会显示正文；增加明确的手动收起状态，正文、译文、要点和笔记在再次点击原文后真正隐藏。导航打开会清除收起状态，保留展开的其他卡片不受影响。

角色采用七种不同的高对比色带和实色标签：背景灰蓝、空白橙、已有工作金、贡献紫、方法蓝、结果绿、局限红。深色主题保留类别区别，角色文字继续显示。

## 原版对照的基线与公式

对照窗口以 PDF 的物理坐标定位原文。正文按照整篇论文选定的字号和基线间距排版。行内公式保留原字形、宽度、上下标和基线。模型只处理带有占位符的正文。列表项和首行缩进从文字层恢复。跨栏句有可确认的连续关系且左栏末尾有足够空间时，续文可沿阅读顺序接排。悬停按两侧各自的位置标出对应文字，点击接排片段可将另一侧滚动到对应原文。图表、独立公式和参考文献为接排范围提供边界。

「页码与导出…」使用 Zotero 的打印引擎排出可选中的译文，再按原页尺寸写入。图表和原公式沿用 PDF.js 渲染的原稿。无法分离的图文区保留原图，完整译文可从对应译页的「完整译文」打开，也会随导出文件附在相应页之后。单元测试覆盖含 TeX 的 OCR 输入、数值、样式、公式分隔、缓存升级和定向重试。原生回归覆盖段落实际基线、原图像素、旋转裁切页、缩放、焦点、导出以及中断恢复。

v1.6.0 在 Zotero 10.0.6 上复核了《Diffusion Policy》的两个版式。其中一版用同一页的生图译稿和相同措辞对照，两条列表分别占 5 行和 6 行，两份 PDF 的行距都约为 15 pt。另一版使用实际保存的解析结果和已配置的翻译模型，第 2、5 页的 20 和 17 个译文块全部原位显示。两页图内英文标签继续使用原图。这些数字对应所列样页。


## 三篇全文对照

v1.7.0 使用同一批官方 MinerU 解析包，在 Zotero 10.0.6 里执行全文翻译与导出。对照基准是三篇论文的全部 11 页，每个原页各生成一张独立的 nature-paper-trans 译图。迭代时复用源文与受保护表达式相同的模型回复。打开列宽、图表或参考文献问题时，可以用以下原页复核。

| 论文 | 原页 | 可观察的结果 |
| --- | --- | --- |
| [UMAP](https://joss.theoj.org/papers/10.21105/joss.00861) | 1–2 | 图标题和 10 个类别标签位于原散点图和色带旁，出版信息、参考文献和独立 DOI 行保持定位。 |
| [chrF](https://aclanthology.org/W15-3049/) | 1–4 | 同一句可以从第 2 页接到第 4 页。第 3 页的表头、表注中文化，91 个小数与 210 段表线的裁片逐一核对。 |
| [imbalanced-learn](https://www.jmlr.org/papers/v18/16-365.html) | 1–5 | 检查两行居中标题、代码注释、表内 72 个勾叉和末页的 14 条参考文献。 |

图内 OCR 在本机工作线程里运行，只在用户点翻译时识别。筛选能和图形分开的英文文字，按实际像素计算留白，在经核实的背景区域内替字。图像复杂、字迹不清、竖排或发生位置冲突时，原图仍可阅读。模型措辞、字体和换行会影响与生图参考的相似度。

并排图片下方成行的任务名也可以识别。插件要求多幅图片下的标签在同一水平线上，并验证标签周围的空白，以保留图片和表线。相邻表头已有同名译文时，图下标签优先沿用同一译法。

## 全文术语与双语导出

DeepRead 借鉴 PDFMathTranslate 的原版双语阅读，以及 BabelDOC 使用论文术语指导翻译的做法。实现位于 Zotero 插件内。[PDFMathTranslate 论文](https://aclanthology.org/2025.emnlp-demos.71/) · [BabelDOC 论文](https://aclanthology.org/2026.acl-demo.25/)

全文英译中时，插件统计跨页重复的短语，优先考虑由原文定义或出现在图表标签中的概念。模型结合对应原文短摘选定译名。翻译请求只使用当前段落中匹配的术语，数学表达式、数字、代码及其原有占位各自保留。打开论文、缩放和导出均可直接复用本机结果。

双语 PDF 的原文一侧使用源页的文字和图形，应用阅读器的裁切和旋转。含可见批注的源页或无法嵌入的源文件采用阅读器已绘制的页面。译文由 Zotero 打印引擎输出，可选择和搜索。补充译文紧跟其对应的译页。

放大后的原图和行内公式按显示密度重新绘制，单页高清画布设有像素上限。导出使用同一套数学字形边界，常规论文页面的行内公式按四倍源坐标采样。

## 文档排版样式

插件从固定的若干源页读取连续正文的字形，估计论文的常用字号。打开任意页、悬停和导出都使用同一份样式。PDF 的裁切、旋转和阅读器缩放仅影响显示比例。采样只使用打开文件的文字层。

以正文字号基准 10 pt、原文行距 12 pt 的论文为例，中文正文使用 9.5 pt 宋体、12.5 pt 行距。插件从同一栏连续正文的基线估计原文行距，为每篇论文确定一套正文与列表行距。缺少足够样本时采用 13.5 pt。正文、题注和标题按实际字宽及合法断点自然换行。短单行可在同一栏的可用范围内排开。连续正文只在原栏空白处微调段距，空间充足时可以略放宽行距。参考文献沿用原 PDF 的字形、编号、换行和悬挂缩进。整页参考文献在导出时沿用原页的矢量文字和链接。论文标题、一级标题、小标题分别为 18、12.5 和 10.5 pt，统一加粗。图题、表题为 9 pt，行距 11.5 pt。简体正文和列表使用内置 Noto Serif SC 的 500 字重，简体衬线题注使用内置 550 字重宋体，无衬线题注使用 500 字重黑体。题注内按原稿加粗的短语保留粗体，常规和斜体西文沿用原有 STIX Two Text 字形。内置 Noto Serif SC 提供回退和加粗字形。无衬线文字使用 Noto Sans SC，西文正文使用 STIX Two Text。正文及题注内部的强调和行内公式保留。图表内部的刻度、图例和单元格在其原有空间内排版。

导出时，将 Zotero 打印引擎产生的译文文字基线对齐到阅读器的排版坐标，以消除打印字体的取整误差。连续正文在同一栏内使用统一的行框。图表、公式、页脚以及绕图引起的栏宽变化划定独立的排版区域。图表和公式旁按原稿的分区独立排版。确实缺少空间时，允许单个文本框少量避让。区域放不下完整译文时，读者可打开本页的「完整译文」，导出在相应页后附全文。

## 大模型调用工具

每批翻译提供单元 `id`、角色、原文和必要的上下文。模型调用 `submit_pdf_translation` 提交每个单元的译文。每个请求的编号只出现一次，公式、数据和引用的占位符也各保留一次。

```json
{
  "translations": [
    { "id": "0:u0", "translation": "实验误差降低了 ⟦D0⟧。" }
  ]
}
```

插件直接消费工具参数。服务拒绝指定函数调用时，插件用相同结构接收 JSON。两者共用本地编号校验、换行和列表标记的整理，以及公式占位符、数字、强调和译文覆盖程度检查。补译只请求校验没通过的单元，`repair_issue` 指明该改的是哪一项。字号、缩进、分栏、公式绘制和参考文献位置由本地渲染器从原稿确定。[Chat Completions 函数调用格式](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

| AI 对话中的请求 | 工具调用 | 本地结果 |
| --- | --- | --- |
| 对照译文正文用了什么字体 | `pdf_fonts({"role":"body"})` | 字体、字号和行距 |
| 译页上方的论文题名用了什么字重 | `pdf_fonts({"role":"runningTitle"})` | 经原始字形和首页题名核对的页眉样式 |
| 查看当前译页的排版状态 | `pdf_layout({"mode":"inspect"})` | 已译单元和需查看完整译文的数量 |
| 请重新排版当前译页 | `pdf_layout({"mode":"apply"})` | 对已有译文重新排字 |
| 检查当前页译文有没有漏译 | `pdf_check_translation({})` | 待译数量、触发校验规则的数量和具体原因 |

页码和单元号从 1 开始。工具返回的校验结果用于说明缺漏和格式问题，译文表述仍取决于模型。相同译文始终使用同一套版式。

## 选页与成品页序

页码使用阅读器显示的 PDF 物理页序，从 1 开始。`2,5-8` 选中五页，`8-` 从第八页读到文末。首次翻译这些页时，插件按连续区间截取页面内容，移除会引入其他源页的 PDF 批注链接，按原始页号保存解析框和译文。跨页续句可使用同一选择中相邻页的原文。指定页面首次翻译会复用已有术语表，全文术语提取仍由「翻译全文」触发。页码选择和输出次序参照公开的使用方式，截取、翻译与成品排版由插件自身实现。[PDF2ZH 页码和输出选项](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/v2.10.2/docs/en/advanced/advanced.md)

「导出已有译文」只导出选中页。并排模式在一张纸上放两种语言，交替模式让每种语言独占一页。原文在先、译文在先都按成品的页序和旋转后的坐标重建内部引用，略过指向选区外的目标。选择「Zotero 文库并打开」会把成品挂到同一论文条目下。独立 PDF 的译稿会放回相同的文库与分类。重复导出相同的页码、版式和译文时，会重新打开已有附件。

单行标题需要更多宽度时，排版器检查本栏实际可用的空白，保留字号和字重。居中标题向两侧对称取宽。源稿把姓名、单位、邮箱分行排印时，新的译文按 PDF 字形的基线分别落位，原有的整段译文可继续从缓存导出。

MinerU 已完成解析而结果包暂时无法下载时，只将任务编号、服务地址和物理页区间存入本机缓存。点击「重试结果下载」向原服务查询下载地址。若原任务过期或已更换账号，重新提交本次选择的页面。

## 原生连续对照

「1:1 对照」打开 Zotero 自带的垂直分屏。两边使用同一附件的 PDF 视图，按原生页框同步页内位置、缩放和旋转。译文层只覆盖需要替换的字形区域。图、独立公式和页码由底层 PDF 视图绘制。可视页离开窗口后释放译文画布，滚动回去从论文缓存恢复。翻译、导出和正在阅读的位置独立。

有原稿字形的行内公式根据源 PDF 基线确定占位宽、高和下沉量。屏幕像素密度只改变裁取清晰度，公式继续使用排版占位的大小。屏幕阅读器从数学对象的无障碍标签读取表达式。OCR 提供的 TeX 优先通过本地 KaTeX 转为 Gecko 原生 MathML，保留上下标和分数结构。

## 原文坐标与对齐边界

同一文本框中，普通字号字形的基线决定译文首行位置，上下标单独处理。绕图正文在窄栏与通栏各保留一个物理起点。相邻段落的译文长短只影响段尾余白，图、公式和下一段的起点限制可用空间。放得下完整一行时才显示该行。较长段落可从「完整译文」读全。

插件从多条源行的共同右边界识别两端对齐。中文由 Gecko 在实际栏宽内分配字间距，基线测量标记独立于正文。绕图或跨页的续行可以填满栏宽，真正的段末自然收尾。重新断行沿用原来的字体、公式和链接，并优先在字间距适当的条件下接近原段高度。原文与译文两侧的悬停框共用同一组 PDF 坐标。

## 翻译速度与完整度

当前页已有可靠 PDF 字形和位置的正文可以在外部解析期间先出译文。布局合并会根据原文和公式占位重用已核对的段落。图内 OCR 可以和正文翻译同时进行，模型请求共用设置里的并发额度。支持推理力度参数的 GPT 和 o 系列模型，首次翻译与提取术语默认请求较低推理力度。

翻译以原段的句意、条件、比较关系和结论为单位。重点核对过度缩短的长段、遗漏的公式占位与引文。检测到异常时对相应段落补译。「页码与导出」中的重译选项可以用新流程更新指定页。原有译文会保留到该段成功替换。

简体表格单元沿用可识别的原文衬线或无衬线字族，常规字使用内置 500 字重。图内有原始字形依据的常规文字自 6 pt 起使用 500 字重；更小的原生图字和 OCR 图字使用常规笔画。源文的粗体和斜体标记仍分别还原。
